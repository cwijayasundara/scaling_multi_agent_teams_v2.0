# Security boundary and operational limits

## Local trusted-tools profile

Models are untrusted decision makers. They receive only explicit role tools. Each tool calls a controller-owned gateway using a secret capability token captured in its closure; identity is never chosen through model arguments. Deep Agents middleware removes default filesystem, execution, planning, and general-purpose delegation tools from the model's exposed tools and blocks attempts to invoke them anyway. The default backend is virtual state; no local shell backend is used.

The controller, gateway, trusted analytical functions, reference grader, dependency installation, Python process, operating-system account, and local storage are trusted. No model-written code is executed. This is an intentionally constrained tool system, not isolation for arbitrary agent code.

Task data is synthetic. The operator chooses the input path through the CLI. Model tools cannot choose paths, credentials, arbitrary SQL, URLs, commands, or external services. Stable event-ID sharding keeps duplicates together. The grader independently checks all row identities, exclusions and numeric results, using its own SQL-based implementation.

## Enforcement

- Server-owned role capabilities and run membership precede dispatch; authenticated identity fields in arguments are rejected.
- Serious forbidden operations stop the whole team. Monitor uncertainty/failure and missing audit storage pause it without executing pending operations.
- Run epochs are checked in the same transaction as durable effects. Task leases have fencing tokens and expiry. Old worker results cannot commit after operator stop or re-leasing.
- Per-agent Ed25519 keys sign every request. Keys live in the same trusted process, so this gives attribution and log-forgery detection, not protection against compromise of that process.
- Agent bearer tokens expire after 5 minutes (`credential_ttl`). Within 60 seconds of expiry the gateway rotates the token after the holder signs a refresh request with its registered key; the old token stops working and `credential.refreshed` is recorded. Refresh is refused once the run is not `RUNNING` or its epoch changed, so stop remains the kill switch; a call past the run deadline pauses the run with `run deadline exceeded`. An expired bearer string presented without its key raises `CredentialExpired`, records `credential.rejected` and quarantines the session's agent (see containment below) without stopping the team. Control-plane service tokens are still per-launch and are not covered.

The separated control plane (`python -m teamlab plane`) adds mutual TLS with pinned server keys between the runtime and its grader, integration, gateway-archive and model-proxy services. Each launch issues a fresh ECDSA P-256 CA (key never written to disk), one server certificate per service and one runtime client certificate; private keys are mode 0600. Connections require TLS 1.3 and a client certificate from that CA; the runtime checks each server's SHA-256 SubjectPublicKeyInfo pin. The peer-UID check still runs before the handshake and the service token after it, so mTLS is an additional factor, not a replacement. The plane CA is per launch and valid for 24 h, so restart the plane at least daily. There is no automatic rotation in this step. Certificates are local and same-host; this is not remote attestation.
- Per-role behaviour profiles (`src/teamlab/behavior_profiles.json`, `behavior-profile-v1`) are reviewed, version-controlled thresholds on calls per action, calls per minute and failures per agent, checked in the gateway after the output filter and before the monitors. A breach is a containment strike against that agent (verdict `CONTAIN`, the call raises `AccessDenied`) and is triaged `needs_human`; the file's version and SHA-256 are recorded in `run.started`, and an invalid file stops the gateway from starting. They are a Foundation baseline written by hand, not a learned one.
- Graduated per-agent containment (`src/teamlab/containment.py`). Each agent is `ACTIVE`, `RESTRICTED` or `QUARANTINED`; the signed `access_policy.json` sets the strike thresholds (restrict at 1, quarantine at 2) and the strikes per source: a behaviour-profile breach (1), an access-policy denial of an already-restricted agent (1), and `credential.rejected` (2, so straight to quarantine). Every strike records `agent.strike`; a state change records `agent.restricted` or `agent.quarantined`. A restricted agent may only read the board. Quarantine revokes all of that agent's gateway sessions (its credentials then raise `AgentQuarantined`, so it can neither act nor spend model budget) and, in the same transaction, returns its leased work to `READY` with a new fence so a teammate can claim it and the old fence is rejected. The collaborative scheduler no longer schedules a quarantined worker, and a worker turn ended by containment does not fail the round. Quarantining the coordinator, the verifier, or a fixed-workflow worker (whose shard cannot be reassigned) pauses the run with `agent quarantined: <agent_id>`. Containment is re-checked in the dispatch transaction: a change while the monitors ran refuses the call and records `action.denied` (`containment-changed-at-dispatch`). Signals that still stop or pause the whole team are unchanged: deterministic blocks (capability violations, identity-field arguments, invalid request signatures, the output filter and deterministic rules) stop it; monitor PAUSE or failure, oversized actions, audit failure, deadlines and budgets pause it. States only move down. There is no un-quarantine through the API, the CLI or the dashboard; `restart` creates a fresh run with fresh agents. Monitoring snapshots (`GET /runs/<id>/snapshot`) expose each agent's state and strikes read-only.
- Shipped configuration is signed and verified before use. `behavior_profiles.json` and the OpenShell sandbox policy `sandbox_policy.yaml` each carry an Ed25519 `.sig` over the file name and SHA-256 of its bytes; the controller verifies every signed config before it writes a run row, the gateway and the OpenShell broker parse or send exactly the bytes that were verified, and `run.started` records each file's signer key id as `config_signers`. A missing, mismatched, edited, unknown-signer or bad signature raises `ConfigIntegrityError` and nothing starts. `teamlab config verify` checks the shipped files; `teamlab config keygen` and `teamlab config sign` create keys and signatures. The default trust anchor is the committed `src/teamlab/config_signers.json`, which detects tampering with the config files but not an attacker who can also edit the signer file. Production must point `TEAMLAB_CONFIG_SIGNERS` at an operator-controlled file outside the repository. Private signing keys never enter git; the development key lives in the git-ignored `.secrets/config-signing.key` (mode 0600).
- Fixed tool work and data sizes are bounded. The runtime never treats a classifier approval as permission to execute a shell or bypass an absent capability.
- Local audit records are outside model tools. Hash chaining detects modifications relative to the recorded chain, but does not prevent a local administrator from rewriting or truncating everything. A loopback MinIO Object Lock check is recorded in [reports/object-lock-qualification.json](reports/object-lock-qualification.json). It is not an AWS account, IAM, or cloud-retention guarantee.
- `teamlab verify-audit` requires every record to carry a valid agent signature. Audit roots created before signed records fail with `unsigned audit record`; this is fail-closed by design, so start a new root rather than re-signing old records. A missing root or `audit.jsonl` is refused rather than reported as zero records.
- The read-only monitoring API uses bearer authentication, binds to loopback, and exposes no approvals, restart, or policy changes. CLI controls inherit the local user's OS permissions. Alert acknowledgement (`teamlab ack`) is operator-only and has no API route, so a compromised dashboard or API client cannot mark alerts as handled; the API serves trace and alert metrics read-only. `acknowledged_by` is advisory attribution from the local OS user name (`unknown` when it cannot be read), not authentication.

The current live classifier combines action and recent cross-agent context. It is a supplementary heuristic using the same model family as the workers, not independent proof of safety. There is no privileged private reasoning access, full-history sabotage detector, or adversarially validated classifier recall claim. Short context windows can miss attacks spread over time. Capability removal remains in force even when a monitor misses intent.

## Explicit non-guarantees

The default trusted-tools deployment does not establish arbitrary-code containment, network namespace enforcement, remote identity/mTLS, production incident paging, or AWS immutable logging. Optional OpenShell, PostgreSQL, and archive adapters require separate deployment qualification. A separated grader, integration service, archive gateway, and model proxy can run as same-user processes; that split is weaker than distinct UIDs, and the runtime still authorizes tools and holds the coordination database. Durable task/graph records and controlled Git integration do not by themselves establish those deployment boundaries. It cannot guarantee prevention of unknown infrastructure exploits. No real external intrusion was attempted or is needed by the tests.

An operator/root compromise, malicious installed dependency, or compromise of the trusted Python process can defeat this local boundary. Do not run untrusted Python files or expose this controller to the public internet. Do not add a host-shell tool to make the demo more capable. Set up and qualify the OpenShell execution profile first.

## Stop and restart

Use the `stop` CLI to revoke the entire run. A provider request already in flight may still finish and be billed. Late model responses and stale result submissions cannot authorize tool effects. There are no untrusted background programs to terminate in this profile.

After review, `restart` creates a clean new run from the captured input rather than continuing old contexts or credentials. It does not automatically repair a broken task or carry forward suspicious artifacts. A new run using the same malicious input may stop again; investigate and correct the cause first.

Keep API secrets in the process environment or a secret manager outside all model-readable inputs. Live API calls send selected synthetic data and tool results to OpenAI. Provider retention settings and local observability retention require separate review before using real data.

## Alert triage

After a run stops or pauses, `execute`, `attack-demo` and `teamlab triage --root R --run-id ID` record one first-pass disposition per alert (`action.denied`, `run.stopped`, `run.paused`, `credential.rejected`, `agent.restricted`, `agent.quarantined`) in `triage_dispositions` and an `alert.triaged` event; the read-only monitoring API serves them at `GET /runs/<id>/triage`. The default triager is a deterministic rule mapping; `--model` (or live mode) uses a single tool-free, strict-schema Luna call per alert over at most 64 prior events (trace `span.*` events are left out of this window and of the gateway monitor's 256-event window), falls back to the rules when its evidence is not a subset of those events or the call fails, and requires a spend budget. Dispositions are recommendations with `decision_owner: human`: triage never changes run state, and containment, restart and disclosure stay with the operator. A triage failure is recorded as `triage.failed` and never replaces the run's own outcome.

## Collaboration and authored execution additions

`--workflow collaborative` preserves the fixed-tool trust boundary while adding bounded task creation/splitting, readable shared notes, dynamic claims, dependency completion, independent per-task verification and round-boundary task recovery. Exact partition coverage, task ownership, leases and run epochs remain deterministic checks. Notes and task titles are untrusted data. Replay task creation is scripted and does not establish autonomous model behavior.

`--workflow authored` permits source authoring and execution only in disposable OpenShell microVM sandboxes, as described in [infra/README.md](infra/README.md). Source is content-addressed and scoped to task/fence/author. Fresh disposable guests execute calculations and independently reproduce submitted artifacts. The protected host reference grader never imports submitted code. Controller-owned Git integration accepts exact verified sources into a private run repository, without remotes or agent-controlled Git options. Local tests use an explicitly named trusted broker double that never evaluates source; those tests establish protocol behavior only.

The OpenShell profile and its opt-in guest tests passed live checks on one macOS development host (OpenShell 0.1.8, `vm` driver). That is not a production audit: no Linux/KVM host has been qualified, OpenShell's VM driver is marked Experimental upstream, and libkrun has no jailer equivalent. Kernel hardening, distinct service UIDs, host observation, AWS immutable audit retention, and a server-enforced storage quota are not established by this release. The PostgreSQL adapter can refuse a connection when `TEAMLAB_DATABASE_QUOTA_BYTES` is below `pg_database_size`; that check is not a tablespace quota. No model-written source executes on the host when the OpenShell gateway is missing, at the wrong version, or fails.

Live mode now runs distinct action and recent-team-context classifier calls. Offline behavioral review includes overlapping action windows, a bounded full note/source index, coverage counts and validated event references. It refuses over-quota evidence rather than silently claiming complete coverage. Reasoning is not observed. All classifiers use the same model family; correlated misses and prompt manipulation remain possible. Versioned development/holdout cases and frozen thresholds were evaluated through the model proxy on 14 November 2026. Development and holdout scenario recall were both 0.0, benign false-positive rates were both 0.0, and coverage was complete. Both failed `min_scenario_recall` 1.0. One live contextual monitor also paused `coordinator/list_tasks`. These are finite-suite results, not universal detector recall.

Live HTTP requests require conservative spend reservations at explicit operator-supplied prices and an experiment request limit. Reservations are shared across workers and monitors and never refunded. Only bounded text Responses requests and fixed function tools are supported by the budget adapter. Configured estimates are not independently verified invoices or protection from incorrect prices. Run inference/tool ceilings remain separately enforced.

Durable graph state contains untrusted observable messages and is accessible only to the trusted runtime. Restart imports only an operator-selected quiescent task checkpoint into a new run, revalidates completed results, revokes old identities and uses clean model contexts. Resuming arbitrary in-flight instructions is refused. Completed authored results require fresh isolated reproduction and Git reintegration before reuse. Local hashes do not authenticate records against an administrator who can rewrite storage.


Pattern-based output filtering blocks plain-text credentials (OpenAI-style keys, AWS access keys, private-key headers, GitHub tokens, JWTs and configured secret values) in gateway requests and redacts emails from model summaries on export; encoded or paraphrased leaks need the Enterprise semantic filter.

Optional `--audit-bucket` sends pre-dispatch decision records to a preprovisioned S3 Object Lock bucket with per-object COMPLIANCE retention and checksummed conditional writes. A missing versioned receipt or write error prevents dispatch and pauses the run. `--require-external-audit` refuses startup without that archive. The adapter does not create buckets, choose cloud credentials, or prove the account/IAM configuration; these remain operator-controlled deployment requirements. Full transcripts and source bundles still need separately controlled retention. The local qualification used MinIO on loopback and is recorded in [reports/object-lock-qualification.json](reports/object-lock-qualification.json). It does not establish AWS IAM or cloud immutability.
